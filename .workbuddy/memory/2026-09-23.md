## spi_demo（STM32U575 + ILI9341 SPI 屏）驱动走查

### 工程事实（已确认）
- 时钟链：HSE 12MHz → PLLM3/N40/R1 → SYSCLK 160MHz；SPI1 时钟源 = SYSCLK，`spi.c:49` 分频 4 → **SCK = 40MHz**
- 画面播放：`Core/Src/bsp_ili9341_4line.c` 的 `LCD_Picture()`（559–611 行）只发一次 `0x2C`，然后按 10 字节一段灌 4 帧数组，`while(1)` 死循环轮播
- 实际参与编译的只有 `assets/array/yuexinmao1.c` ~ `4.c`（CMakeLists.txt 46–53 行）；磁盘上另有 5~16 共 12 个数组未编译
- 固件 `build/Debug/spi_demo.bin` = 1,882 KB / 2,048 KB（约 92% 满）；4 帧占 600 KB，16 帧全屏需 2.4 MB → 放不下
- 动画有效像素包围盒（16 帧并集）= 94×84 → 裁剪后单帧仅 15792 B（原 153600 B，省 90%）；16 帧裁剪后共 247 KB，可全部塞进片内 Flash

### 数据手册关键页码（ILI9341_DS_V1.05，共 239 页）
- P236 / §18.3.3：3 线 SPI 写时钟周期 min 100ns（10MHz）
- **P237 / §18.3.4：4 线 SPI 写时钟周期 min 100ns → SCK 上限 10MHz**（工程 40MHz，超 4 倍）
- P231 / §18.3.1：8080 并口 tWC min 66ns（15MHz）
- P225 / §15.4 复位时序：tRW ≥ 10µs；tRT Sleep In ≤5ms / Sleep Out ≤120ms；Note7：释放 RESX 后须等 5ms 才能发命令，且 120ms 内不能发 Sleep Out(0x11)
- P114 / §8.2.22 RAMWR(2Ch)：收到 2Ch 后 column/page 寄存器复位到 SC/SP
- **P194 默认值表：IFCTL(B3h) 的 WEMODE 默认 = 1**（P133 §7.5 说明 WEMODE=1 时超出窗口的数据会让地址复位并回卷继续写）→ 这是"只发一次 0x2C 就能连播多帧"的手册依据
- P40-41 / §7.1.11：多参数命令被新命令打断时，已发参数生效、未发参数**保持旧值**（`ILI9341_SetCursor` 只发 2 个参数还能工作的原因，但很脆弱）
- P134 / §8.2.33 COLMOD(3Ah)：DBI[2:0]=101 → 16bit/pixel；工程 0x55 ✓
- P127 / §8.2.29 MADCTL(36h)：默认 00h；工程最终值 0x08（BGR=1，MY/MX/MV=0）✓
- P179 / §8.3.17 PWCTRL2(C1h)：只有 BT[2:0]，**没有 SAP**；BT=001 → AVDD=VCI×2, VGH=VCI×7, VGL=-VCI×3
- P178 / §8.3.16 PWCTRL1(C0h)：GVDD = 2.85 + 0.05×VRH；默认 VRH=0x21(4.50V)，工程 0x1B(4.20V)
- P164 / §8.3.7 DISCTRL(B6h)：**4 个参数**（默认 0A/82/27/XX），工程只发 2 个（0A/A2），且把 SS 从 0 改成 1
- P155 / §8.3.2 FRMCTR1(B1h)：RTNA=0x10 → 119Hz（默认 1B → 70Hz）
- P213 §12：CSX 可永久接地（工程未接 CS，合法）
- P209 / §10：TE 输出"should be used to avoid Tearing Effect"；工程开了 0x35 但 TE 引脚未接

### 已识别问题
1. SPI 40MHz 超手册 4 倍（合规需 ≤10MHz）
2. 每 10 字节一次 `HAL_SPI_Transmit`，调用开销占主导；根因是超时实参写死 1(ms)
3. `ILI9341_WriteRAM()`（76–82 行）重复发送两次（且是死代码）
4. `ILI9341_SetCursor()`（91–103 行）只发 2 个参数，2Ah/2Bh 各需 4 个 → 依赖"未发参数保持旧值"，EC/EP 变成隐式全局状态
5. `ILI9341_Display_Dir()` 里 `DFT_SCAN_DIR` 是 static 且函数内赋值 → switch 中 R2L_D2U / U2D_R2L 为死分支；且 36h 在 Init 先写 0x48 又被覆盖为 0x08
6. 0x11 在复位释放 ~10ms 处发出，未满手册 Note7 的 120ms
7. C1h 注释 `//SAP[2:0];BT[3:0]` 是从 ILI9325 系列抄来的，手册里 C1h 只有 BT[2:0]
8. 死代码占比过半：`ILI9341_WriteRAM` / `ILI9341_SetArea` / `_HW_FillFrame` / `LCD_DrawRect` / `LCD_DrawCircle` / `_HW_DrawLine` 全部无调用者

### 寄存器量化公式（从手册原文推导，可复用）
- `C0h` VRH[5:0]：**GVDD(V) = 2.85 + 0.05 × VRH**（规格 3.0~5.0V）。默认 0x21=33→4.50V；工程 0x1B=27→4.20V
- `C1h` BT[2:0]（无 SAP！）：**AVDD = VCI×2**（所有档位）；BT=000 → VGH=VCI×7, VGL=-VCI×4；BT=001 → VGH=VCI×7, VGL=-VCI×3；010 → VCI×6/-VCI×4；011 → VCI×6/-VCI×3。约束 AVDD≤5.5V、|VGH-VGL|≤32V
- `C5h`：**VCOMH(V) = 2.700 + 0.025 × VMH**；**VCOML(V) = -2.500 + 0.025 × VML**。默认 31/3C → 3.925V / -1.000V，幅度 4.925V（规格 4.0~5.5V）；工程 30/30 → 3.900V / -1.300V，幅度 5.200V
- `C7h`：bit7 = nVM（须置 1 才让 VMF 生效），bit6:0 = VMF[6:0] 是**纯 DC 偏移，不改变 VCOM 幅度**（64=无偏移，55=偏移 -9）。默认 0xC0（无偏移）；工程 0xB7 → 偏移 -9 → VCOM 中心下移 0.225V
- `CBh`：P4 的 REG_VD[2:0] 控 Vcore（100→1.6V）；P5 的 VBC[2:0] 控 DDVDH（010→5.8V）
- `F7h`：Ratio[1:0] 控 DDVDH 倍率（10=2×VCI，11=3×VCI；00/01 保留）。**手册此页位域与默认值自相矛盾**（Ratio 合并格跨 D5:D4，按此读默认 0x10 得保留值 01）
- `B1h`：RTNA[4:0]=16 → 119Hz；默认 27 → 70Hz
- `E0h/E1h`：各 15 个参数（第 1 个是 VP63[3:0]/VN63[3:0] 占 4 bit，其余 VP62..VP0 各占 6 bit）
- `F2h`：Enable 3G（3 倍伽马），0=关

### 工程初始化序列的"血统"
前段（`CFh/EDh/E8h/CBh/F7h/EAh` 的值）= **Adafruit 通用版原样照抄**；
后段（`C0h=0x1B`、`C1h=0x01`、`C5h=0x30,0x30`、`C7h=0xB7`、`B1h=0x00,0x10`、`B6h` 只发 2 参 `0x0A,0xA2`、`E0h/E1h` 伽马）= **2.8 寸中文模块的调优值**，不是手册默认值。判断依据：手册 §8.4 各扩展寄存器的 Default 表。

### 刷新画面所需寄存器（最小集与分档）
- **每次刷新真正必须的只有 3 条**：`2Ah` CASET + `2Bh` PASET + `2Ch` RAMWR；若窗口未变且用连续流，可只发 `2Ch`
- `2Ch` 每次都把地址指针复位到 (SC,SP)；`3Ch` RAMWRC 是**从上次停止处续写**（不重设窗口）——局部刷新省命令用
- 硬件滚动：`33h` VSCRDEF（6 参数 TFA/VSA/BFA，默认 0000/0140/0000，约束 TFA+VSA+BFA=320）+ `37h` VSCRSADD（VSP，2 参数）；手册 P129 Note(1) 明确"新指针在下一场扫描生效，**以避免撕裂**"→ 滚动天然免撕裂；`37h` 在 Partial 模式下被忽略
- 局部显示（省电，不省 MCU 写入）：`30h` PTLAR（SR/ER，默认 0000/013F）+ `12h` PTON / `13h` NORON
- 刷新时**绝不能重发**：`C0h/C1h/C5h/C7h/CBh/CFh/EDh/E8h/EAh/F7h/E0h/E1h/B6h`（上电配置，重发会重新软启动电荷泵与伽马，表现为闪屏/花屏）
- 依赖：改 `36h`(MADCTL) 后必须重发 `2Ah/2Bh`；改 `3Ah`(COLMOD) 会改每像素字节数（16bpp=2B / 18bpp=3B）；`F6h` IFCTL 的 WEMODE/ENDIAN 会改 `2Ch` 的溢出与字节序行为
- 同步相关：`34h` TELOFF / `35h` TELON（00=Mode1 仅 V-sync，01=Mode2 V-sync+H-sync）/ `44h` Set_Tear_Scanline / `45h` Get_Scanline
- `2Eh` RAMRD 可读回显存（Restriction 同样写明无长度限制）；但需模组引出 SDO/MISO，且 4 线 SPI 读要先送 1 个 dummy byte

### 寄存器写入点清单（精确行号，2026-09-23 复扫）
共 **25 个不同命令码**、31 处写入点。初始化集中在 `bsp_ili9341_4line.c:243-358`，之后只剩刷新路径。
- 重复写入：`36h` 写 2 次（L286 的 0x48 被 `Display_Dir` L216 的 0x08 覆盖 → 首次是废指令）；`2Ah/2Bh` 写 3 次（L346/L340 完整 4 参数 → L218-223 完整 → `SetCursor` L96/L100 **只发 2 参数**）；`2Ch` 写 2 次（L66 `WriteRAM_Prepare` 被 `Clear` 调用 → `LCD_Picture` L567 再发一次）
- **L567 那次 `2Ch` 冗余但无害**：`Clear()` 正好写满 76800 点，靠 WEMODE=1 已自动回卷到 (0,0)，重发只是保险
- `Clear()` 能正常工作，是因为 `SetCursor` 只改 SC/SP，EC/EP 保留 L346/L340 设的全屏值 —— 又一个"缺参数命令保留旧值"的隐式依赖
- 从未使用的寄存器：所有读命令（`04h`/`0Ah`-`0Fh`/`DAh`-`DCh`）、`01h` SWRESET、`10h` SLPIN、`28h` DISPOFF、`B0h` IFMODE、`B4h` 反相控制、`B8h~BFh` 背光、`D0h~D2h` NV、`33h`/`37h` 滚动、`30h`+`12h` 部分显示、`34h`/`44h`/`45h` TE、`2Eh`/`3Eh` 显存回读、`F6h` IFCTL

### 想做"显示单张图片"时的注意点
- 全屏图：Init 里 L340/L346 已把窗口设成 240×320，**只需发 `2Ch` + 数据**（当前 `LCD_Picture` 就是这么做的）
- 局部图（小于全屏）：**必须**先发完整的 `2Ah`+`2Bh`（各 4 参数），且**不能再依赖 WEMODE 回卷**（回卷只在当前窗口内生效），每张图都要重发 `2Ch`
- ⚠️ **链接陷阱**：`bsp_ili9341_4line.c` 里的 `ILI9341_SetArea`/`ILI9341_SetCursor`/`ILI9341_WR_REG`/`ILI9341_WR_DATA`/`ILI9341_WriteRAM_Prepare` 都是 `inline`，而头文件里是非 inline 原型。按 C99/gnu11 规则，**这类函数只能在同一个 .c 内调用**；从 `main.c` 调用会 `undefined reference`。新增的显示函数应写在 `bsp_ili9341_4line.c` 内部（同 TU），既避开链接问题也不用改 CMakeLists。
- `ILI9341_SetArea` 有 `old_x0..old_y1` 静态缓存（L112），首次调用会长 0xFFFF 所以必定全量发送，与 `2Ch` 配合是安全的。
- 两个必须对齐的点：① 字节序 —— 取模数组高字节在前，对应 `F6h` IFCTL 的 ENDIAN 默认 0；② 扫描方向 —— 取模的扫描方式要对应 `36h` MADCTL 的 MY/MX/MV，不对齐会镜像或错位。
