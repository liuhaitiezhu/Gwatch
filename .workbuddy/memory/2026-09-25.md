## 走查：`ILI9341_SetCursor` 为什么只设起点不设终点（根因定位）

驱动文件仍是 `Core/Src/bsp_ili9341_4line.c`（17678 B / 610 行，**未编译进工程的新版**，属 D 层自己的文件）。

**新发现（此前未记录）——"只设起点"写法的出处：**

`_HW_DrawPoint()`（L395-412）里内联了和 `ILI9341_SetCursor`（L91-103）**完全相同**的"只发 2Ah/2Bh 各 2 字节"套路，然后接着发 `wramcmd` + **恰好 1 个像素**。
→ 画单点时终值（EC/EP）根本用不到，写法在那个场景下是**正确的**。
→ `ILI9341_SetCursor` 是把这段原样抽成函数，但**使用场景变了**（后续要连写 N 个像素），终点就从"无关"变成"关键"。

**依赖链（全部靠隐式状态成立）：**
- 终点 EC/EP 全工程**只在 `ILI9341_Init()` L340/L346 设过一次** = `0x00EF` / `0x013F`（239 / 319）
- `ILI9341_SetArea()`（L114，唯一发满 4 参数的"正确"版本）**零调用者**，是死代码
- 且 `SetArea` 在 `.c` 里是 `inline`、`.h` 里是非 inline 原型 → 按 C99 规则不产生外部定义，**从别的 .c/.cpp 调用必然 undefined reference**
- 两处调用点恰好成立：`ILI9341_Clear()` L379（窗口=全屏，正好；且 76800 点全靠 WEMODE=1 回卷）、`_HW_FillFrame()` L431（xlen=ex-sx+1 恰好不超过窗口右边界）

**结论**：这不是设计，是"从 DrawPoint 抄过来时场景变了没跟上"。一旦前面有人调用过 `SetArea` 收窄窗口，`Clear()` 会只清左上角一小块。修法：`SetArea(x,y,x,y)` 语义化，或补齐 4 参数。

## 溯源：51 原版驱动对比（用户新提供 `C:/Users/1/Desktop/CubeMx_Project/2.8 寸电容屏数据手册/ILI9341+CTC2.8_4SPI(C51)/main.c`，226 行，与百度网盘那份同源）

**关键结论：`SetCursor 只设起点` 这个缺陷不是从 51 原版来的。** 51 版全文件共 10 个函数：
助手类 `Delay1ms`(L19) / `delay_ms`(L31) / `SPI_RW`(L39) / `LCD_CD_DATA`(L54) / `LCD_CD_REG`(L62)；
显示类 `LCD_Init`(L70) / `LCD_SetArea`(L176，发满 4+4 参数，**正确**，全文仅被 L204 调用一次) / `LcdWirteColorData`(L191) / `LCD_Clear`(L200) / `main`(L215)。
**全文 grep `cursor`/`光标` 零匹配 → 没有 SetCursor，也没有任何画点/画线/画矩形原语。** → STM32 驱动里的 `SetCursor` + `_HW_*` 系列来自 **uGUI 移植模板**，是两份不同来源的代码被拼在一起。

| `35h` TE | 无 | 新增 `00`（但 TE 脚没接出来） |
| `21h` 反相 | 无 | 新增 |

前 18 条（CFh/EDh/E8h/CBh/F7h/EAh/C0h/C1h/C5h/C7h/3Ah/B6h/F2h/26h/E0h/E1h/2Bh/2Ah）**逐字节一致**。
⚠️ MX 位差异意味着：若取模数据按 51 版做过，在当前 STM32 驱动上会**左右镜像**。

### 51 原版自身缺陷（及是否被带入）
| 缺陷 | 位置 | 带入 STM32 驱动？ |
|---|---|---|
| `LCD_RESET=0;` 重复，第二句应为 `=1`（低电平 11ms 而非 1ms） | L74-77 | ❌ 已修 |
| 逐字节切 CS（`LCD_Clear` 一屏 76800 次 CS 翻转；手动 SPI ~214KB/s） | L54-68, 191-198 | ❌ 已修（`ILI9341_Command` 一事务一 CS） |
| `C1h` 注释 `//SAP[2:0];BT[3:0]` 错误（手册只有 BT[2:0]） | L109 | ✅ 带进来（STM32 `bsp:277`） |
| `B6h` 只发 2 参数（手册要 4 个；SS 被翻成 1） | L122-124 | ✅ 带进来（STM32 `bsp:296-298`） |
| `DATA_H/DATA_L` 死宏 | L9-10 | ✅ 带进来但未用 |
| 签名用 `unsigned int`（C51=16bit / ARM=32bit） | L176/191/200 | ❌ 已改 `uint16_t` |
| `LCD_MISO` 读了不用（L49），且 `P0=0`（L72）把 MISO 脚也拉低 → 将来读 ID 必须先写 1 | L49/L72 | — |
| `Delay1ms()` 硬编码 `@12.000MHz`，而 `0x11` 后 `delay_ms(120)` 是协议要求 | L19-37, L172 | — |
| `main()` 嵌套 `while(1){...; while(1);}` 外层多余 | L219-224 | — |

**51 版反而更安全的一点**：`LCD_SetArea` **无缓存**，每次实发；STM32 版加了 `old_x0..old_y1` 缓存（`bsp:112`）反而引入"缓存与芯片脱节"风险。

**SPI 时序核对（手册 §7.6.2 P35 原文）**：host 在 SCL **下降沿**置数据，ILI9341 在**上升沿**采样 → 即 SPI mode 0。51 版 `SPI_RW`（`SCK=0→置数据→SCK=1`）**符合 mode 0，写法正确**。
