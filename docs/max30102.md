# MAX30102 驱动与后续显示接口

本分支实现 MAX30102 红光/红外原始 PPG 采集，已经接入原生 FreeRTOS 启动流程。
不需要在 `main.c` 再调用初始化或创建任务。心率 bpm、SpO₂ 百分比、手指检测和界面控件尚未实现；原始 ADC 计数不能直接当作这些数值。

## 接线与默认配置

| 项目 | 本工程配置 |
| --- | --- |
| SCL / SDA | 现有 I2C1，PB6 / PB7，与 FT6336、SHT20 共用总线互斥锁 |
| 地址 | 7 位 `0x57`；传给 STM32 HAL 的地址为 `0xAE` |
| 供电 | 按用户原理图：VDD 为 1.8 V，VLED+ 为 3.3 V，GND/PGND 接地 |
| INT | 原理图网络名 `I2C_INT3`，当前工程没有对应 MCU 引脚映射；本版定时查询 FIFO，不依赖 INT |
| 采集模式 | `0x09 = 0x03`，红光 + 红外双通道 |
| 采样配置 | `0x0A = 0x27`，100 组/秒、411 μs、18 位、4096 nA ADC 量程 |
| FIFO | `0x08 = 0x00`，不平均、不覆盖旧数据，满阈值为 32 组 |
| 中断使能 | `0x02 = 0xA0`，记录 FIFO 满和环境光抵消溢出；MCU 不使用外部中断 |
| LED 电流码 | 红光、红外均为 `0x24`，标称约 7.2 mA，实际光学结构需实测调整 |
| 任务 | `max30102`，优先级 2，栈 512 个 32 位字（2 KiB） |
| 读取周期 | 正常每轮结束延时 20 ms；失败后延时 1000 ms 再初始化 |

LED 电流宏位于 `Core/Inc/bsp_max30102.h`，也可以通过构建宏覆盖。固定采样率和 ADC 配置应一起修改；目前不提供动态切换采样模式的 API。
FIFO 容纳约 320 ms 的数据。任务按最多 4 个批次读取，每批最多 8 组（48 字节 FIFO 数据），每批后释放总线；实际调度和总线时序仍须上板确认。

本次没有修改 `.ioc`、GPIO、I2C 初始化、屏幕 SPI 配置或 TouchGFX 生成文件。

寄存器、双通道数据顺序和 FIFO 行为参考 [Analog Devices MAX30102 数据手册 Rev 1](https://www.analog.com/media/en/technical-documentation/data-sheets/max30102.pdf)，主要见第 10–20 页。

## 驱动 API

驱动仅由 `max30102` 任务拥有。外部任务不要同时调用驱动 API；界面读取下述应用队列。

- `MAX30102_Init()`：检查 `PART_ID == 0x15`，等待复位完成，清 FIFO 并开始采集。复位等待期间释放 I2C1。复位最多等待约 100 ms，各次 I2C 操作另有 20 ms 上限。
- `MAX30102_ReadFIFO(samples, capacity, &info)`：`capacity` 为 1–8。`OK` 且 `info.count == 0` 表示暂时没有数据。每组依次为红光、红外各 3 字节，保留有效的低 18 位。
- `MAX30102_Shutdown()`：停止采样，之后调用 `Init()` 重新启动。仅供拥有任务未来加入低功耗控制时使用；当前任务持续采样。
- `MAX30102_StatusString(status)`：取得错误说明。

FIFO 满时写/读指针可能相等，驱动结合满状态位区分满与空。发现溢出计数后不发布该批数据；部分读取失败也不会把残缺数据作为成功样本发布，必须重新初始化。掉电复位通过 `PWR_RDY` 检测。
环境光抵消溢出 `ALC_OVF` 保留在 `info.interrupt_status`，表示原始光学数据受到影响。

## 后续接入屏幕

当前数据流：

```text
MAX30102 FIFO -> max30102 任务 -> 长度 1 的最新结果队列
                                  |
                        App_MAX30102_TryRead()
                                  |
                       后续 Model::tick() / MVP / View
```

在手写的 `TouchGFX/gui/src/model/Model.cpp` 中包含 `app_max30102.h`，从 `Model::tick()` 调用 `App_MAX30102_TryRead(&reading)`，再沿现有 `ModelListener -> Presenter -> View` 路径更新控件。硬件调用保留在 `#ifndef SIMULATOR` 中。
本次只预留应用接口，尚未修改 Model、Presenter、View 和页面布局。

`App_MAX30102Reading` 包含：

- `sample.red` / `sample.ir`：最新原始计数。
- `sample_count`：从任务启动以来成功读取的样本对总数，包括发生后续错误前已读到的样本；重试不会清零。
- `tick_ms`：读取/报告时的 HAL 毫秒计数，**不是** ADC 每个采样点的准确时刻。
- `status` / `interrupt_status` / `lost_samples`：驱动或采样错误、中断状态、硬件丢样计数（最多 31）。
- `valid`：成功取得新数据，且本轮没有观察到环境光抵消溢出；**不表示**已检测到手指或获得有效心率。

队列通过值复制并覆盖旧结果。界面过慢不会阻塞采样；失败也会发布 `valid=false`，I2C/FIFO/复位等错误会清零本次原始值，连续 500 ms 没有数据则报告采样超时并重新初始化。
上电第一次报告可能为 `status=OK, valid=false`，表示已配置完成、正在等待第一组数据。

后续心率/血氧算法应在 `MAX30102_Task()` 中标注的位置消费每批的**全部样本**，遇到丢样、复位或通信错误时重置算法窗口，再把计算结果放入应用数据结构。
最新结果队列会跳过中间采样点，不适合作为心率算法输入。控件操作和 `invalidate()` 应保留在 GUI 任务。

## 串口与验证

沿用 USART1 / 115200。正常约每秒报告一次，状态或有效性变化时立即尝试报告，例如：

```text
[MAX30102] n=100 t=1234 RED=72000 IR=81000 valid=1 flags=0x00
[MAX30102] t=2234 ERROR: I2C error lost=0
```

以上数值仅为格式示例。日志使用 `App_UART_TryWrite()`，队列满时丢弃该条日志，避免 UART 反压导致 FIFO 来不及读取。GUI 状态队列独立更新。

```powershell
./tests/max30102/run.ps1 -Compiler C:/mingw64/bin/gcc.exe
cmake --build --preset Debug --parallel 2

git diff --check
```

主机测试使用真实的 `bsp_max30102.c`、`app_max30102.c` 和 `app_freertos.c`，模拟 HAL 和 FreeRTOS。覆盖 ID/复位/配置、空/满 FIFO、回绕、分批读取、通道顺序、18 位掩码、溢出、掉电、部分读取失败、互斥锁释放、启动资源回收、采样重试、无数据超时、计时回绕、队列复制以及串口拥堵。

尚未烧录或取得板上证据。上板时检查 `0x57` 应答与供电，观察 `sample_count` 随时间增长、遮挡传感器时 RED/IR 的变化、触摸与温湿度是否继续工作，并验证断线重连与长时间运行的溢出情况。
构建与模拟测试不证明真实 I2C 电气时序、光学信号质量或心率/血氧准确度。
