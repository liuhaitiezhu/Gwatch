# TouchGFX 显示与 TE 同步验证

运行现有主机测试：

```powershell
./tests/touchgfx_display/run.ps1
```

测试编译真实的 `TouchGFXHAL.cpp` 和 `bsp_ili9341_4line.c`，用模拟接口代替
TouchGFX 渲染器、FreeRTOS 调度和 STM32 硬件。测试结果验证软件逻辑，不代表
板上 TE 波形、调度延迟或防撕裂效果已经验证。

## 当前流程

1. PA11 的 TE 下降沿经 `TouchGFX_NotifyVSync()` 通知 GUI，并通过
   `xSemaphoreGiveFromISR()` 释放独立的发送同步信号量。中断内不发送 SPI。
2. `beginFrame()` 开始新一轮绘制；每次 `flushFrameBuffer(rect)` 只收集变化范围。
3. `endFrame()` 完成渲染收尾，确认帧缓冲绘制完成，丢弃旧的 TE 信号量令牌，
   再等待一个新的 TE。等待期间只阻塞 GUI 任务。
4. 得到新 TE 后，设置 ILI9341 写入窗口，以阻塞式 SPI 发送 RGB565 数据。
   全部发送完成后 `endFrame()` 才返回，单帧缓冲才能进入下一轮绘制。

变化区域合并为一个最小覆盖矩形，因此同一轮只等待一次 TE；区域之间的未变化像素
也可能被发送。没有变化区域时不等待 TE、不发送像素。

TE 等待上限是 100 ms。已准备好数据但等待超时，或 SPI 发送失败时，调用项目现有的
`Error_Handler()`；不会用未同步的发送作为超时回退。当前错误处理会停止固件。
这个超时保护发生在准备发送时，不是全局的 TE 断线检测器。

## 主机用例

- 初始化序列中的标称 61 Hz 参数。
- 绘制结束且收到新 TE 之前，不发送窗口命令或像素。
- 绘制前、绘制中、上一轮发送中收到的 TE 不会提前放行下一轮发送。
- 清除旧令牌和进入等待之间到来的 TE 不丢失；多个 TE 可安全合并。
- 多个绘制区域合并、全屏无参数刷新、空帧不重发。
- TE 超时、信号量创建失败、调度器状态不合适以及各阶段 SPI 失败。
- 裁剪、非连续行跨度、RGB565 字节顺序、完整帧数据和源缓冲保持不变。

## 板上确认

使用逻辑分析仪同时观察 PA11（TE）、SPI1 SCK 和 DCX：

- 核对 TE 周期是否接近标称 61 Hz 对应的 16.4 ms。
- 改变局部数字或按钮，确认相关 SPI 写入在准备完成后的 TE 下降沿之后启动，
  测量下降沿到发送的延迟以及整个区域的发送时间。
- 单独测试整屏切换和大面积动画；任务唤醒、SPI 发送、扫描方向与扫描位置
  都会影响撕裂，采用该同步流程并不保证任意更新面积都无撕裂。

当前保留用户设置的 PA11 下降沿、上拉和 EXTI11 优先级 5。
`.ioc`、TouchGFX `target/generated` 和框架源码不需要为这套同步逻辑改写。
